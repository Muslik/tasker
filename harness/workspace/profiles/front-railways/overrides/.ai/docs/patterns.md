# Архитектурные паттерны и технические решения

Этот документ описывает конкретные паттерны и технические решения, используемые в Front Railways. Он дополняет общую архитектуру и служит практическим руководством для разработчиков.

## 1. Паттерн "Адаптер" для работы с данными

### 1.1 Концепт:

**Расположение:** `/src/entities/`
**Назначение:** Преобразование данных между форматами сервера и клиента

### 1.2 Принципы адаптеров:

- **Чистые функции** — без побочных эффектов.
- **Двусторонняя конвертация** — `toClient`/`toServer`.
- **Изоляция логики** — отделение представления от получения данных.
- **Вычисляемые поля** — добавление удобных для клиента свойств.
- **Преобразование для форм (Client-Form-Client)** — когда структура данных, удобная для UI, отличается от структуры, требуемой для компонента формы, используется дополнительный уровень адаптации `клиент-форма-клиент` (`toClient`/`toForm`).

## 2. Паттерн компонентной архитектуры

- **Умные контейнеры** (страницы/контейнеры) отвечают за бизнес-логику: получение данных через хуки, управление состоянием форм, обработку событий и координацию дочерних компонентов.
- **Глупые компоненты** (блоки/UI-элементы) занимаются исключительно отображением: получают данные через пропсы, рендерят интерфейс и передают события наверх, не зная о бизнес-логике. Такое разделение обеспечивает переиспользуемость, простоту тестирования и поддержки кода.
- **Единственная ответственность**: один компонент — одна задача.
- **Композиция**: сложные UI строятся из простых блоков.

## 3. Паттерн работы с формами (react-hook-form)

- **Единообразная работа с формами**: Все формы в приложении следуют стандартной архитектуре: использование хука `useForm` для управления состоянием, типизация значений через интерфейс `FormValues` и `enum Fields`.

## 4. Стилизации компонентов

### 4.1 сlsx

Для комбинации нескольких статических классов из SCSS-модулей, а также для динамического добавления условных классов используется библиотека `clsx`.

## 5. Паттерн оптимизации производительности

### 5.1 Мемоизация

Для оптимизации производительности используются: `useMemo` для кэширования результатов дорогих вычислений; `useCallback` для стабилизации ссылок на функции и предотвращения лишних ререндеров дочерних компонентов; `React.memo` для мемоизации целых компонентов на основе сравнения пропсов.

**Когда НЕ применять:** Избегайте мемоизации примитивных вычислений, которые не влияют на производительность. Если у функции нет зависимостей, выносите её за пределы компонента.

---

**Ключевые принципы всех паттернов:**

1.  **Консистентность** — одинаковый подход во всем проекте.
2.  **Типобезопасность** — максимальное использование TypeScript.
3.  **Тестируемость** — все паттерны легко покрываются тестами.
4.  **Переиспользование** — компоненты и хуки легко переносятся.
5.  **Производительность** — встроенная оптимизация во все решения.
