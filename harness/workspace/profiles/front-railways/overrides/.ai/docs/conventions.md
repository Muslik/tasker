# Соглашения по коду Front Railways

Этот документ описывает наши соглашения по стилю кода, структуре компонентов и инструментам разработки.

## 1. Языки и инструменты

### 1.1 Приоритет TypeScript:

- **Все новые файлы** создаем с расширением `.ts` или `.tsx`.
- **Строгая типизация** — избегаем `any`, используем `unknown` при необходимости.
- **Интерфейсы vs типы** — используем `type`.

### 1.2 Автоматические инструменты:

```bash
# Автофикс
pnpm agent:eslint-for-staged

# Генерация компонентов
pnpm plop [имя_компонента] [путь от src/components/]
```

## 2. Структура и именование

### 2.1 Файлы и папки:

**Компоненты:**

```
ComponentName/
├── index.ts              # Экспорт компонента
├── ComponentName.tsx     # Основной файл компонента
├── ComponentName.scss    # Стили (SCSS модуль)
├── constants.ts          # локальные константы (при необходимости)
├── hooks.ts              # локальные хуки (при необходимости)
├── helpers.ts            # локальные хелперы (при необходимости)
└── types.ts              # TypeScript типы (при необходимости)
```

**Примечание:** Если количество хуков, хелперов или типов в компоненте 2 или более, их следует выносить в отдельные папки (`hooks/`, `helpers/`, `types/`).

**Именование:**

- **PascalCase** для компонентов: `HotelCard`, `RoomSettings`.
- **camelCase** для функций и переменных (в том числе констант): `fetchHotelData`, `isLoading`, `defaultTimeout`.

### 2.2 Импорты:

**Правила:**

- Используем **относительные пути** для импортов внутри модуля.
- Используем **абсолютные пути** от `src/` для импортов из файлов, находящихся вне модуля.
- **Не импортируем** всю библиотеку, если можно импортировать часть.

## 3. Запрещенные практики

Это список практик и конструкций, от которых мы сознательно отказались.

### 3.1 Не использовать `React.FC`

Вместо `React.FC<Props>` следует использовать явное указание типа пропсов: `(props: Props) => ...` или `({ prop1, prop2 }: Props) => ...`.
