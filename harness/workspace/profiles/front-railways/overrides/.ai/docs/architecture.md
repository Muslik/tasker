# Архитектура Front Railways

## 1. Общая стратегия развития

Проект представляет собой **зрелое приложение**, в котором сочетаются проверенные временем и современные технологии. Общая стратегия — **постепенный рефакторинг и модернизация** без кардинальной перестройки.

### 1.1 Принципы архитектуры:

- **Прагматичный подход** — пересматриваем архитектуру по мере необходимости
- **Постепенная модернизация** — новый функционал на современном стеке
- **Обратная совместимость** — поддержка legacy кода до полной миграции
- **Качество через тестирование** — высокий уровень покрытия новой функциональности

## 2. Технологический стек

### 2.1 🆕 Современный стек (приоритет для новых фич):

**Frontend Framework:**

- **React 18** + **TypeScript 4.9.3** — основа для всего нового кода
- **@reduxjs/toolkit@1.9.7** — управление серверным состоянием, замена Redux для данных
- **React Router DOM v5** + **connected-react-router** — маршрутизация

**UI Framework:**

- **@ott/ пакеты** — основная UI-библиотека

**State Management:**

- **Redux Toolkit** — для глобального и серверного состояний
- **React встроенное состояние** — для локального UI состояния

**Development Tools:**

- **pnpm** — менеджер пакетов
- **Plop** — генерация компонентов по шаблонам
- **ESLint + Prettier** — линтинг и форматирование
- **Size Limit** — контроль размера бандла

### 2.2 ⚠️ Legacy стек (выводится из эксплуатации):

- **Redux + redux-form + redux-thunk** — старое управление состоянием
- **JavaScript файлы** — постепенно мигрируются в TypeScript

## 3. Архитектурные слои

### 3.1 Презентационный слой (UI):

```
src/components/
├── atoms/              # ⚠️ LEGACY: Базовые неделимые UI элементы (BookTotal, Timer, TrainCarrierLogo)
├── molecules/          # ⚠️ LEGACY: Составные компоненты из атомов (Alert, Direction, RouteInfo)
├── organisms/          # ⚠️ LEGACY: Сложные компоненты бизнес-логики (CreditCard, PassengerInfoRow)
├── pages/              # 🆕 MODERN: Страницы приложения (Book, SeatSelection, RailwaysPay)
├── layout/             # Layout компоненты (App, Routes, HeaderPartner)
├── icons/              # Иконки (TrainIcon, MealIcon, WifiIcon)
├── containers/         # Контейнеры с бизнес-логикой (SortContainer, HeaderSearchInfoContainer)
├── skeletons/          # Компоненты загрузки (BookFormSkeleton, SeatSelectionSkeleton)
├── providers/          # React Context провайдеры
├── alternates/         # Альтернативные версии компонентов
└── base/               # Базовые общие компоненты
```

**Архитектурная стратегия:**

- ⚠️ **Legacy Atomic Design** - постепенно выводится из эксплуатации
- 🆕 **Модульная архитектура** - новый подход для всех новых компонентов
- Переход от atoms/molecules/organisms к функциональным модулям

**Принципы новой архитектуры:**

- Модули группируются по функциональности, а не по размеру
- Компоненты ответственны только за отображение
- Максимальное переиспользование через композицию
- Четкое разделение между презентационными и контейнер-компонентами

### 3.2 Слой данных (Data Layer):

```
src/
├── slices/             # 🆕 MODERN: Redux Toolkit слайсы по доменам
│   ├── railways/       # Железнодорожная логика (bookData, calendar, places, pay)
│   ├── hotels/         # Гостиничная логика (hotelsConfig)
│   └── common/         # Общие слайсы (user, passengers, authModal)
├── redux/              # ⚠️ LEGACY: Классический Redux (модули, саги, селекторы)
│   ├── modules/        # Старые Redux модули
│   ├── sagas/          # Redux-Saga эффекты
│   └── selectors/      # Селекторы состояния
├── hooks/              # Кастомные React хуки для бизнес-логики
├── types/              # TypeScript типы и интерфейсы
└── helpers/            # Утилиты и хелперы
```

**Архитектурная стратегия:**

- ⚠️ **Legacy Redux + Saga** - постепенно мигрируется
- 🆕 **Redux Toolkit + слайсы** - современный подход для нового функционала
- **Domain-driven разделение** - группировка по бизнес-доменам (railways, hotels, common)

**Принципы:**

- Изоляция бизнес-логики от UI через хуки и слайсы
- Единая точка истины в Redux store
- Типизация всех данных через TypeScript

### 3.3 Слой маршрутизации:

```
src/components/layout/Routes/   # Конфигурация маршрутов приложения
src/components/pages/          # Страницы-компоненты (RailwaysIndex, SeatSelection, Book, RailwaysPay)
```

**Структура маршрутов:**

- **/** - Главная страница поиска ЖД билетов
- **/:route/train** - Выбор мест в поезде
- **/:route/passengers** - Заполнение данных пассажиров
- **/:route** - Страница результатов поиска (SERP)
- **/pay/:bookId** - Страница оплаты заказа
- **/ticket/:bookId** - Страница заказа с билетами

**Принципы:**

- React Router v5 + декларативная конфигурация
- Lazy loading через `lazyWithRetry` для оптимизации bundle size
- Error Boundary для обработки ошибок маршрутизации
- Skeleton компоненты для улучшения UX при загрузке
- Поддержка white-label через hash routing

## 4. Работа с данными

### 4.1 Архитектура данных:

**🆕 Современная архитектура:**

```
API Server ←→ Redux Toolkit Slices ←→ Custom Hooks ←→ Components
```

**⚠️ Legacy архитектура (не используется в новом коде):**

```
API Server ←→ Redux Modules ←→ Redux-Saga ←→ Selectors ←→ Components
```

**Поток данных:**

1. **API запросы** — через RTK Query или прямые вызовы в слайсах
2. **Redux Store** — центральное хранилище состояния (slices для нового, modules для legacy)
3. **Custom Hooks** — инкапсуляция бизнес-логики и доступа к store
4. **Components** — отображение данных и обработка пользовательских действий

**Стратегия миграции:**

- ⚠️ **Redux-Saga** — больше не используется в новом коде, только поддержка существующего
- 🆕 **RTK Slices** — все новые API интеграции только через Redux Toolkit
- **Домены:** railways, common, hotels — группировка по бизнес-логике

### 4.2 Принципы работы с данными:

- **Единственный источник истины** — Redux Toolkit Query cache.
- **Автоматическая инвалидация** связанных запросов.
- **Обработка ошибок** на уровне запросов и UI.
