# Руководство для AI-агента

Ты — AI-ассистент в проекте Front Railways. Твоя задача — помогать в разработке, строго следуя приведенным ниже правилам и процессам.

## 📜 Главные правила

1.  **Источник истины** — это Jira-тикет и комментарии разработчика. Не придумывай недостающую информацию, а задавай уточняющие вопросы.
2.  **Не делай лишний рефакторинг**. Выполняй только те изменения, которые требуются по задаче.
3.  **Используй существующие паттерны**, описанные в документации.

## 🚀 Основной рабочий процесс

1.  **Изучи контекст**. Перед началом работы ознакомься с ключевыми документами:

    - `docs/project.md` — чтобы понять бизнес-цели и структуру проекта.
    - `docs/architecture.md` — чтобы понять техническую архитектуру.
    - `docs/patterns.md` и `docs/conventions.md` — чтобы следовать принятым в проекте подходам.

2.  **Создай файл задачи**. Для каждой новой задачи создавай файл в формате `.context/tasks/[название-ветки].md`.

3.  **Заполни шаблон** в файле задачи (источник истины - текущая задача в https://jira.twiket.com/browse/[номер задачи], если нет доступа к jira.twiket.com, запроси у разработчика описание задачи):

**Шаблон задачи:**

```markdown
# [RR-XXXX] Название задачи

## Продуктовые требования

### Цель

[Описание цели и проблемы, которую решаем]

### Ключевые возможности

- [ ] Функция 1
- [ ] Функция 2

## Техническая декомпозиция

- [ ] Этап 1: [Описание]
- [ ] Этап 2: [Описание]

## Чек-лист текущего этапа

- [ ] Конкретное действие 1
- [ ] Конкретное действие 2

## Договоренности и решения

[Фиксируем все решения по ходу работы]

## Финальный чеклист

- [ ] Соответствие архитектурным подходам из `docs/architecture.md`
- [ ] Соответствие паттернам из `docs/patterns.md`
- [ ] Соблюдение code conventions из `docs/conventions.md`
- [ ] Отсутствие критических ошибок линтера
```

## 2. Во время разработки

1.  **Следуй current stage**: Работай только в рамках текущего этапа из чек-листа.
2.  **Предложи план изменений**: Перед любыми изменениями в коде предложи план и получи подтверждение.
3.  **Отмечай прогресс**: Помечай выполненные пункты в чек-листе.
4.  **Фиксируй решения**: Записывай все договоренности в секции "Решения".

## 3. Завершение этапа

1.  **Проверка качества**: Запусти `pnpm agent:eslint-for-staged` для промежуточного этапа и `pnpm agent:check-ts-by-build` для финального.
2.  **Переход к следующему этапу**: Отметь текущий этап как завершенный.

## 4. По окончании финального этапа проверь работу по финальному чеклисту в шаблоне

## Коммиты

Одна строка, без тела. **Никаких подписей и трейлеров** — ни `Co-Authored-By`,
ни «Generated with …», ни упоминаний инструмента.

Формат: `TICKET-123: краткое описание` (ключ задачи — из ветки). Допустим тип:
`TICKET-123: fix: ...`, `TICKET-123: chore: ...`.

За референсом стиля — последние коммиты репозитория: `git log --oneline -20`.

## Worktree

Worktree создаются и удаляются через `wt`:

- `wt <ветка>` — подключить worktree к **существующей** ветке (локальной или с origin).
  Ветки нет → ошибка с подсказкой, новая НЕ создаётся.
- `wt -b <ветка> [--base <ref>]` — создать **новую** ветку + worktree.
- `wt` — выбрать существующую ветку через fzf.
- `wt cd [ветка]` — перейти в worktree (без аргумента — fzf).
- `wt list` — worktree текущего проекта.
- `wt rm <ветка> [--force]` — удалить worktree.
