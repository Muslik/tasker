# jira-issue — собрать/создать Jira-задачу по шаблонам компании

Тебя вызывает wrapper `jira-new` в одной из операций (см. префикс `OP:` в промпте):

- **OP: assemble** — собери черновик и выведи РОВНО содержимое файла-черновика (начни со строки `---`).
  Без преамбулы и комментариев. В режиме сборки в Jira ничего НЕ создавай (только читай/фетчи).
  Ссылки Loop/Confluence из запроса загрузи САМ (см. «Вход») и наполни ими тело (summary, Окружение/
  Шаги/Факт/Ожидание, Ссылки). **ВСЕГДА** выводи черновик начиная с `---`, даже если контента мало или
  ссылку не прочитать: ссылку клади в тело, нерешённое — в `TODO`. Никогда не выводи только прозу.
- **OP: create** — прочитай файл-черновик и создай в Jira РОВНО то, что в нём (шапка=поля, тело=описание),
  через **REST-скрипт по Bash**: этот путь одинаков для подписочных Codex и Claude и не зависит от
  доступности MCP. Ничего не добавляй. Пустые поля не ставь.
- **OP: preview** — как `OP: create`, но НИЧЕГО не создавай. Обработай TODO (влей ответы, убери блок) и
  выведи РОВНО итоговый черновик-файл (начни со строки `---`: та же YAML-шапка + описание), как уйдёт в Jira.
  БЕЗ преамбулы, БЕЗ таблиц, БЕЗ пояснений «что сделал». Только чистый шаблон.

## Формат файла-черновика (канонический)
Один или несколько узлов. Каждый узел = YAML-шапка между `---`, затем тело описания. Несколько узлов
разделяй строкой `=== УЗЕЛ ===`. В шапку включай ТОЛЬКО релевантные типу поля: `variant` — лишь для
Story; для Bug/Epic/Research/Task строку `variant` не выводи.

```
---
project: AVIA            # проект (из промпта); epic→1 проект, дети могут в другой
type: Bug                # Epic | Story | Bug | Research | Task
variant:                 # ТОЛЬКО для Story (FE|BE); для прочих типов строку НЕ выводи
summary: Краткая суть одной строкой
team: Transportation
assignee: Dzhabrail Markhiev
pm: Oksana Venetskaya
sprint: backlog
labels: []
estimate:                # НЕ выдумывать — впиши число или оставь пусто
parent:                  # epic-link/parent, напр. AVIA-123
links:                   # напр. "blocks AVIA-456"
---

<тело по шаблону типа>

> TODO (открытые вопросы — ответ пиши строкой СРАЗУ НИЖЕ вопроса; при создании ответы вольются в описание, а сам блок TODO в тикет НЕ попадёт):
> - ...
> - ...
```

Поля шапки бери из `"${TASKER_SKILLS_ROOT}/jira-issue/config.yaml"` (`defaults`), переопределяй промптом.
Приоритет: явное в промпте > `defaults` > пусто (и строкой в TODO). Оценку НИКОГДА не выдумывай.

## Проект
Из промпта («в AVIA», «epic в TRIP»). Нет в промпте → оставь `project:` пустым и добавь строку в TODO.

## Тип задачи — проверяй по проекту
Перед тем как проставить `type`, ПРОВЕРЬ типы проекта через Bash:
`"${TASKER_HARNESS_BIN}/with-env" curl -s -H "Authorization: Bearer $JIRA_TOKEN" "$JIRA_BASE_URL/rest/api/2/project/<KEY>"` → поле `issueTypes[].name`
(`with-env` = `"${TASKER_HARNESS_BIN}/with-env"`, подмешивает $TASKER_HARNESS_ENV_FILE). Поставь
ТОЧНОЕ имя типа, как в проекте (учти RU/EN: Bug↔Баг, Story↔История, Task↔Задача, Epic↔Эпик).
Если запрошенного типа в проекте НЕТ — подставь ближайший существующий (нет Research → Task/Story;
нет Task/Checkpoint → Task/Задача) и ОБЯЗАТЕЛЬНО отметь подмену строкой в `TODO`.

## Структура графа — ТОЛЬКО из промпта
«эпик + 3 задачи (FE story, bug, research)» → ровно эти узлы (1 Epic + 3 ребёнка с `parent:` на эпик).
Источник (Loop/Confluence) наполняет СОДЕРЖАНИЕ узлов, но НИКОГДА не создаёт лишние узлы.
Если в промпте ссылка — загрузи и наполни ею тело:
- **Loop** (`*.loop.ru`): запусти через Bash `"${TASKER_SKILLS_ROOT}/loop/scripts/fetch-thread.mjs" <url>` — вернёт markdown треда.
- **Confluence**: в headless MCP недоступен. Попробуй `curl` к Confluence REST, если настроен; иначе
  вынеси в `TODO` «вставь текст Confluence вручную».

## OP: create — как создавать (headless: Bash + REST, без MCP)
Создание — через скрипт `"${TASKER_SKILLS_ROOT}/jira-edit/scripts/jira_update_issue.py"`
(токен подхватывает сам из $TASKER_HARNESS_ENV_FILE; ad-hoc curl звать через `"${TASKER_HARNESS_BIN}/with-env"`).
1. Прочитай файл-черновик (`Read`). `description` = тело как ПРОСТОЙ ТЕКСТ (Jira не рендерит markdown —
   никаких `###`/таблиц), переносы строк сохраняй.
   **Блок `> TODO` обработай и УБЕРИ из описания:** ответы, вписанные под вопросами, влей в нужные секции
   (Окружение/Шаги/Факт/Ожидание) или поля (project/assignee/…); неотвеченные вопросы перенеси в секцию
   `Открытые вопросы:` в конце описания (чисто, без `>`); сами строки `> TODO …` и `> -` в тикет НЕ включай.
2. Тип сверь: `curl -s -H "Authorization: Bearer $JIRA_TOKEN" "$JIRA_BASE_URL/rest/api/2/project/<KEY>"` (`issueTypes`).
3. По каждому узлу:
   - тело → временный файл (`f=$(mktemp)` и записать туда тело);
   - создай: `"${TASKER_SKILLS_ROOT}/jira-edit/scripts/jira_update_issue.py" --create --project <KEY> --type "<точный тип>" --summary "<summary>" --description-file "$f"`;
   - из ответа возьми КЛЮЧ созданной задачи;
   - доп. поля: assignee/labels — через `--field` (напр. `--field assignee='{"name":"..."}'`). Кастомные
     team/sprint/estimate — резолв ID через `curl .../rest/api/2/field`; не резолвится → ПРОПУСТИ и допиши
     в вывод «проставь team/sprint вручную». Пустое не ставь, оценку не выдумывай.
4. Граф: сначала Epic → ключ → детям проставь parent/epic-link (`--field` с ID epic-link = ключ эпика).
5. Верни: `КЛЮЧ — summary — $JIRA_BASE_URL/browse/КЛЮЧ`. При сбое на узле — остановись, верни созданные
   ключи и упавший узел.
